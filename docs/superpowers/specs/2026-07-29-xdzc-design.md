# 修仙搜打撤 - 设计文档

## 概述
一款网页端纯文字道具风格的修仙放置增量游戏，核心玩法为「修仙搜打撤」，全程以低门槛挂机放置为核心，兼顾路径规划策略感和可视化探索体验。

---

## 一、架构与文件结构

### 1.1 技术栈
- **纯 HTML/CSS/JS**，零依赖，零构建步骤
- 双击 `index.html` 即可在浏览器中运行

### 1.2 文件结构

```
搜打撤/
├── index.html              # 主入口
├── css/
│   └── style.css           # 暗色修仙主题样式
└── js/
    ├── config.js           # 静态配置数据（地图/道具/境界/事件）
    ├── state.js            # 玩家状态与存档管理
    ├── exploration.js      # 探索系统（地图/路径/移动/事件）
    ├── search.js           # 搜索系统（容器/品质动画/自动装袋）
    ├── combat.js           # 战斗系统（自动回合制）
    ├── cultivation.js      # 修仙系统（境界/打坐/三属性升级）
    ├── settlement.js       # 结算系统（撤离/拖拽整理/储物筛选）
    ├── market.js           # 坊市交易系统
    └── main.js             # 入口+UI渲染调度
```

### 1.3 文件职责与依赖

| 文件 | 职责 | 依赖 |
|------|------|------|
| config.js | 所有静态数据定义 | 无 |
| state.js | 玩家对象、localStorage存档、离线收益 | config |
| exploration.js | 路径规划、自动路径生成、移动动画、赶路事件 | state, config |
| search.js | 10×20容器生成、品质转圈动画、自动装袋逻辑 | state, config |
| combat.js | 自动回合制战斗、伤害飘字、胜负判定、掉落 | state, config |
| cultivation.js | 境界突破、打坐收益、三属性升级 | state, config |
| settlement.js | 撤离整理界面（拖拽摆放）、储物袋→储物戒筛选 | state |
| market.js | 坊市出售、灵石兑换 | state, config |
| main.js | 页面初始化、视图切换、全局事件绑定、UI渲染 | 全部 |

### 1.4 数据流向
```
config.js（静态数据）→ state.js（运行时状态）→ 各系统模块（读写state）→ main.js（触发UI更新）
```

## 二、数据模型

### 2.1 境界体系
9大境界 × 9小层 = 81级

```
炼气(1-9) → 筑基(1-9) → 金丹(1-9) → 元婴(1-9) → 化神(1-9) → 炼虚(1-9) → 合体(1-9) → 大乘(1-9) → 渡劫(1-9)
```

- 突破消耗对应丹药，成功率随境界升高而降低
- 突破成功解锁对应地图

### 2.2 地图数据（9张）

| 地图 | 对应境界 | 进入灵石 | 道具价值范围 |
|------|----------|----------|-------------|
| 凡人谷 | 炼气 | 0 | 10 - 5,000 |
| 灵兽林 | 筑基 | 500 | 50 - 25,000 |
| 幽冥渊 | 金丹 | 2,000 | 200 - 100,000 |
| 天柱峰 | 元婴 | 8,000 | 800 - 400,000 |
| 混沌海 | 化神 | 25,000 | 3,000 - 1,500,000 |
| 九幽殿 | 炼虚 | 80,000 | 10,000 - 5,000,000 |
| 仙界门 | 合体 | 250,000 | 40,000 - 20,000,000 |
| 轮回境 | 大乘 | 800,000 | 150,000 - 80,000,000 |
| 鸿蒙界 | 渡劫 | 3,000,000 | 500,000 - 300,000,000 |

- 每张地图7个固定点位
- 进入地图无境界限制，仅需灵石门槛
- 每张地图内部均有完整5档品质分布，价值按地图等级递增
- 跨地图品质价值对齐：低阶地图极品 ≈ 高阶地图上品

### 2.3 道具数据（100-150种）

**品质分级**：

| 品质 | 圈数 | 转圈时长 | 价值倍率 | 颜色标识 |
|------|------|----------|----------|----------|
| 普通 | 1圈 | 1秒 | ×1 | #c8c8c8 白灰 |
| 良品 | 2圈 | 2秒 | ×3 | #4ade80 青绿 |
| 上品 | 3圈 | 3秒 | ×10 | #60a5fa 天蓝 |
| 极品 | 4圈 | 4秒 | ×30 | #c084fc 紫色 |
| 传说 | 5圈 | 5秒 | ×100 | #fbbf24 金色 |

- 1圈 = 1秒，普通1秒，每级品质+1秒
- 串行点亮：前一个转圈完成并点亮后，下一个才开始转圈

**体积规格**：1×1, 2×2, 3×3, 2×3, 4×5

每个道具数据结构：
```javascript
{ id, name, width, height, quality, baseValue, mapId, type }
```

### 2.4 事件类型

| 事件 | 效果 |
|------|------|
| 遭遇妖兽 | 触发战斗 |

## 三、核心游戏流程

### 3.1 完整循环
```
洞府 → 地图选择 → 路径规划 → 地图移动 → 点位搜索 → 撤离整理 → 坊市出售 → 洞府
```

### 3.2 路径规划
- **手动模式**：点击点位依次加入路径，再次点击取消
- **自动模式**：系统随机选3-5个可达点位
- 路径确定后显示预估总时间和预估事件数

### 3.3 移动与事件
- 头像沿路径CSS transition平滑移动
- 每段路径有30%-50%概率触发随机事件
- 事件类型：战斗、机缘、陷阱、迷路等

### 3.4 搜索流程
1. 抵达点位 → 10×20容器界面渐显
2. 道具按体积预摆放在格子内，初始全部暗态
3. **串行转圈点亮**：按品质顺序，一个道具转圈完成后点亮并显示名称，下一个才开始转圈（普通→良品→上品→极品→传说）
4. 全部显形后 → 系统按单格价值自动排序
5. **智能替换装袋**：逐个尝试装入储物袋；若空间不足，则与袋中已有物品比对，**丢弃多个低品质且占格多的物品，腾出空间放入高品质且占格少的物品**，持续优化储物袋内容

### 3.5 战斗系统
- 自动回合制，双方轮流攻击
- 伤害飘字向上漂浮淡出
- 包含暴击、闪避机制
- 战败损失少量低价值道具，自动跳转下一点位
- 战胜后掉落战利品自动收入储物袋

### 3.6 撤离整理（核心体验）
- 左侧展示储物袋道具（按实际尺寸比例）
- 右侧为储物戒网格
- **拖拽交互**：从左侧拖到右侧空格摆放
- **自动选取按钮**：按单格价值自动填充
- 可在储物戒内重新排列已放入道具
- 确认后剩余道具自动销毁

### 3.7 坊市交易
- 储物戒中道具列表
- 一键出售获得灵石
- 灵石反哺三属性养成、境界突破

## 五、核心算法

### 5.1 自动路径生成
随机选3-5个可达点位，优先从邻近点位中选择，保证路径合理性。

### 5.2 品质转圈→点亮
按品质对应圈数（1圈=1秒）旋转后点亮格子，显示道具。
- 普通1圈/1秒 → 良品2圈/2秒 → 上品3圈/3秒 → 极品4圈/4秒 → 传说5圈/5秒
- 串行执行：前一个转圈完成后点亮，下一个才开始

### 5.3 智能替换装袋
1. 计算每个道具的单格价值（总价值/占位格数），从高到低排序
2. 逐个尝试装入储物袋
3. 若空间不足，与袋中已有物品比对：寻找可以被丢弃的低单格价值物品组合，腾出足够空间
4. 丢弃低价值占格多的物品，放入高价值占格少的物品
5. 持续优化，直到无法再通过替换提升总单格价值为止

### 5.4 离线收益
```
elapsed = now - lastOnline (最多24小时)
修为增益 = 悟性 × 10 × (elapsed / 1000)
```

### 5.5 存档
- localStorage 自动保存，每30秒触发
- 包含版本号用于兼容升级

## 七、约束与规则

- 纯 HTML/CSS/JS，无外部依赖
- 所有道具纯文字展示，无图标资源
- 局内储物袋和局外储物戒均可通过灵石扩容
- 战斗无硬核惩罚，战败仅损失少量道具
- 离线收益上限24小时
- 自动存档，玩家数据安全可靠
